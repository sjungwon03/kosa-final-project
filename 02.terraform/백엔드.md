# Terraform Backend 상태 및 복구 계획

---

## [2026-05-19] 장애 — MinIO 백엔드 소실

### 원인
- `02-run.sh prod apply k8s` 실행 (k8s.tfvars 단독 사용)
- 단일 state(`prod/terraform.tfstate`) 기준으로 k8s.tfvars에 없는 VM을 전부 destroy 대상으로 판단
- state에 있던 minio-01(2470), siem-01(2290) Ceph RBD 디스크 삭제됨
- minio-01 디스크 소실 → MinIO 서비스 다운 → **terraform backend 접근 불가**

### 현재 상태
- minio-01 (kosa24/2470): VM conf 존재, Ceph 디스크 소실 → 기동 불가
- siem-01 (kosa22/2290): stopped 상태, 디스크 소실 여부 미확인
- dns-02 (kosa23/2312): 소실 가능성 있음 (미확인)
- terraform state: MinIO 다운으로 접근 불가, 사실상 초기화 필요
- `main.tf`: 로컬 백엔드(`backend "local" {}`)로 임시 변경 완료 (배포 필요)

### 근본 원인
단일 state + 역할별 tfvars 분리 구조에서 `-target` 없이 apply 시 state에 있는 타 역할 VM이 destroy됨
→ 사양 변경 등 부분 apply 시 반드시 `apply all <VM명>` 형식으로 실행해야 함

### 복구 순서

> **전제**: GitLab 작업 완료 후 진행

**1. 유령 VM config 제거**
```bash
# [kosa24] minio-01
rm /etc/pve/nodes/kosa24/qemu-server/2470.conf

# [kosa22] siem-01 디스크 확인
rbd info rbd-team4/vm-2290-disk-0 2>&1
# "No such file" 이면:
rm /etc/pve/nodes/kosa22/qemu-server/2290.conf

# [kosa23] dns-02 확인
qm list | grep 2312
# 없으면 재배포 대상
```

**2. 로컬 백엔드로 전환 (로컬 → 컨트롤 노드 배포)**
```bash
# [로컬] main.tf 이미 local backend로 변경 완료
bash 03.ansible/03-deploy-to-control.sh

# [컨트롤 노드]
cd ~/workspace/terraform/env/prod
terraform init -reconfigure -input=false
terraform state list   # 빈 state 확인
```

**3. minio-01 재배포**
```bash
# [컨트롤 노드]
bash ~/workspace/terraform/02-run.sh prod apply all minio-01
```

**4. MinIO Ansible 재구성**
```bash
ANSIBLE_CONFIG=~/workspace/ansible/ansible.cfg \
  ansible-playbook -i ~/workspace/ansible/inventories/prod/hosts \
  ~/workspace/ansible/playbooks/site.yml --limit minio
```

**5. MinIO 정상 확인 후 S3 백엔드 복원**
```bash
# [로컬] main.tf — local backend 주석, s3 블록 주석 해제 후 배포
bash 03.ansible/03-deploy-to-control.sh

# [컨트롤 노드] 로컬 state → MinIO로 마이그레이션
cd ~/workspace/terraform/env/prod
terraform init -migrate-state -backend-config="key=prod/terraform.tfstate" -input=false
```

**6. siem-01, dns-02 재배포**
```bash
bash ~/workspace/terraform/02-run.sh prod apply all siem-01
bash ~/workspace/terraform/02-run.sh prod apply all dns-02
```

## 현황 (2026-05-18)

### MinIO Backend
- 엔드포인트: `http://172.16.30.70:9000`
- 버킷: `terraform-state`
- 실제 state 파일: `prod/terraform.tfstate` (65KB)
- `prod/k8s/`, `prod/services/` 등 하위 폴더: **빈 폴더** (Gemini가 per-role 분리 시도 중 생성, 내용 없음)

### 02-run.sh key 변경 이력
- 원래: key 없음 (로컬 state)
- Gemini 수정 후: `key=prod/${ROLE}/terraform.tfstate` (역할별 분리, **빈 state 참조 문제 발생**)
- 현재 수정: `key=prod/terraform.tfstate` (단일 파일, 정상)

## 할 일 순서

### 1단계: 동기화 (로컬 → 컨트롤 노드)
```bash
# [로컬]
bash 03.ansible/03-deploy-to-control.sh
```

### 2단계: state 실제 내용 재확인
```bash
# [컨트롤 노드]
cd ~/workspace/terraform/env/prod
terraform init -reconfigure -backend-config="key=prod/terraform.tfstate" -input=false
terraform state list
```

### 3단계: 이미 떠있는 VM state 복구 (minio-01)
```bash
# [컨트롤 노드] minio-01 실제 VMID/node 확인 후
terraform import -var-file=tfvars/all.tfvars \
  'module.vms.proxmox_virtual_environment_vm.ubuntu["minio-01"]' \
  "kosa24/2470"
```

### 4단계: monitor-01 처리
- tfvars에서 node kosa23→kosa21, VMID 2396→2196으로 변경된 상태
- Proxmox에 기존 VM(kosa23/2396)이 있으면: 수동 제거 후 `terraform apply services monitor-01`
- 없으면: 그냥 `terraform apply services monitor-01`

### 5단계: 신규 VM 순서대로 배포
```bash
bash ~/workspace/terraform/02-run.sh prod apply k8s
bash ~/workspace/terraform/02-run.sh prod apply haproxy
bash ~/workspace/terraform/02-run.sh prod apply vault
bash ~/workspace/terraform/02-run.sh prod apply services nexus-01
bash ~/workspace/terraform/02-run.sh prod apply services cicd-01
bash ~/workspace/terraform/02-run.sh prod apply services siem-01
```

## 주의사항
- `all.tfvars`로 apply 시 state에 없는 VM이 plan에서 destroy 대상이 될 수 있음 → 반드시 개별 VM 단위(`TARGET_VM` 인자)로 실행
- monitor-01 tfvars 변경(node/VMID)으로 인해 Terraform이 destroy+recreate 시도할 수 있음
