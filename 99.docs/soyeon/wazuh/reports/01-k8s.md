## 02) 보완 방안
| 번호 | 취약점 | 보완 방안 |
|---|---|---|
| 1 | Gitea 세션 고정 (CVE-2018-18925) | Gitea를 1.5.4 이상 최신 버전으로 업그레이드. 업그레이드 전 기존 세션 전체 무효화 처리 |
| 2 | Harbor 하드코딩 패스워드 (CVE-2026-4404) | Harbor를 2.15.0 초과 버전으로 업그레이드. 즉시 불가한 경우 설치 후 admin 패스워드를 강력한 값으로 즉시 변경 |
| 3 | ArgoCD 초기 패스워드 시크릿 미삭제 | 패스워드 변경 후 시크릿 즉시 삭제: `argocd account update-password` 실행 후 `kubectl delete secret argocd-initial-admin-secret -n argocd` |
| 4 | ArgoCD 익명 접근 허용 | 익명 사용자 비활성화: `kubectl patch cm argocd-cm -n argocd --type merge -p '{"data": {"users.anonymous.enabled": "false"}}'` |
| 5 | ArgoCD 네트워크 정책 미적용 | NetworkPolicy 적용으로 argocd 네임스페이스 외부 접근 차단: `kubectl apply -f argocd-netpol.yaml` |
| 6 | ArgoCD 구버전 | 최신 보안 패치 버전으로 업그레이드: `helm upgrade argocd argo/argo-cd --version [최신버전] -n argocd` |
| 7 | API Server 감사 로그 미수집 | kube-apiserver에 audit policy 설정 후 Wazuh Agent가 `/var/log/kubernetes/audit/audit.log` 수집하도록 `01-agent_log_collect.sh` 반영 |
| 8 | 컨테이너 로그 수집 미흡 | ArgoCD 파드 로그 전용 localfile 설정 추가 또는 파드명 기반 필터링 룰 적용 |

## 04) 잔여 위험 및 특이사항

- **Harbor CVE-2026-4404**는 2026년 3월 공개된 최신 취약점으로, 아직 패치 버전 적용 전인 경우 즉각 패스워드 변경이 최우선 조치임
- **ArgoCD**는 k8s 클러스터 전체에 배포를 제어하는 GitOps 도구이므로, 탈취 시 전체 클러스터에 악성 워크로드 배포가 가능함 — 다른 취약점보다 우선순위를 높게 처리 권장
- **API Server 감사 로그**는 현재 Wazuh 수집 대상에 미포함 상태로, 내부자 위협 또는 권한 탈취 발생 시 사후 추적이 불가능함 — `01-agent_log_collect.sh` 업데이트 필요
- k8s-master-01의 대표 IP는 VIP(172.16.30.30)와 실제 VM IP(172.16.30.31)가 구분되며, Wazuh Agent는 실제 VM IP 기준으로 등록됨
