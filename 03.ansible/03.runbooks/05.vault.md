# Vault

**스택**
- HashiCorp Vault: 시크릿 관리, PKI 인증서 발급
- Raft (통합 스토리지): 별도 외부 스토리지 없이 노드 간 합의

**구성**
- vault-01: 172.16.30.21 (최초 init 대상)
- vault-02: 172.16.30.22
- vault-03: 172.16.30.23
- API 포트: 8200 / 클러스터 포트: 8201
- TLS

> `site.yml`에서 vault.yml은 주석 처리 상태 (반드시 단독으로 실행)


## Vault 구축 (설치)

> 최초 1회 실행

**배포**
```bash

bash ~/terraform/terraform-run.sh prod apply vault

# Ansible 서비스 구성
ANSIBLE_CONFIG=~/ansible/ansible.cfg \
  ansible-playbook \
  -i ~/ansible/inventories/prod/hosts \
  ~/ansible/playbooks/vault.yml
```

**검증**
```bash
# Ansible 접속 확인
ANSIBLE_CONFIG=~/ansible/ansible.cfg \
  ansible -i ~/ansible/inventories/prod/hosts \
  vault -m ping

# 직접 접속 확인
ssh kosa@172.16.30.21
```

**초기화**
- **vault-01에서만 1회 실행**: 결과(Unseal Key, Root Token)는 반드시 안전한 곳에 저장
- 키 5개 중 3개가 있어야 Unseal 가능 (Shamir 비밀 분산)
- Root Token은 초기 설정 후 폐기 권장, 이후 별도 정책 기반 토큰 사용

```bash
# [vault-01]
export VAULT_ADDR="http://127.0.0.1:8200"
vault operator init

# 출력
# Unseal Key 1: xxxx
# Unseal Key 2: xxxx
# Unseal Key 3: xxxx
# Unseal Key 4: xxxx
# Unseal Key 5: xxxx
# Initial Root Token: hvs.xxxx
```

**잠금 해제(Unseal)**
- init 완료 후 **각 노드에서** 실행 (Unseal Key 3개 입력)

```bash
export VAULT_ADDR="http://127.0.0.1:8200"

vault operator unseal  qwZhZwNs+5c/N/2DPo66SQnZPIvTCpifHG6WcCSZrws4 # Key 1 입력
vault operator unseal  9Wzdh8PeLnIjtmXoARyanW2B/Uxfn9LniWZq6dERYWbt # Key 2 입력
vault operator unseal  ssLfzhuwL6vsYdfLdj/pfa3LO5BmN/ubIIwvg7VJT7H+ # Key 3 입력

# 완료 후 확인
vault status
# Initialized    true
# Sealed         false  ← Unseal 완료
# HA Enabled     true
```

## Vault PKI 활성화

> vault-01 (Active 노드)에서 실행 — 루트 CA → 중간 CA → 롤 순서로 구성

**루트 CA 활성화**
```bash
# [vault-01] vault login 후 실행
export VAULT_ADDR="http://127.0.0.1:8200"
vault login  # Root Token 입력

vault secrets enable pki
vault secrets tune -max-lease-ttl=87600h pki

# 루트 CA 인증서 생성 (10년)
vault write -field=certificate pki/root/generate/internal \
  common_name="Internal Root CA" \
  ttl=87600h > /tmp/root_ca.crt
```

**중간 CA 활성화**
```bash
# [vault-01] 중간 CA 활성화
vault secrets enable -path=pki_int pki
vault secrets tune -max-lease-ttl=43800h pki_int

# [vault-01] 중간 CA CSR 생성
vault write -format=json pki_int/intermediate/generate/internal \
  common_name="Internal Intermediate CA" \
  | jq -r '.data.csr' > /tmp/int_ca.csr

# [vault-01] 루트 CA로 서명
vault write -format=json pki/root/sign-intermediate \
  csr=@/tmp/int_ca.csr format=pem_bundle ttl=43800h \
  | jq -r '.data.certificate' > /tmp/int_ca.pem

# [vault-01] 서명된 중간 CA 등록
vault write pki_int/intermediate/set-signed certificate=@/tmp/int_ca.pem
```

**롤 생성 및 인증서 발급 테스트**
```bash
# [vault-01] 롤 생성
vault write pki_int/roles/internal-services \
  allowed_domains="svc.local,k8s.local,sec.local,mgmt.local" \
  allow_subdomains=true \
  max_ttl=720h

# [vault-01] 발급 테스트
vault write pki_int/issue/internal-services \
  common_name="test.svc.local" \
  ttl=24h

# certificate: 발급된 인증서
# private_key: 개인 키 (발급 시 1회만 출력 — 즉시 저장)
# ca_chain: CA 체인 (중간 CA + 루트 CA)
# serial_number: 인증서 시리얼
```

**TLS 활성화**
- PKI 구성 완료 후 수행 (Vault API를 HTTP → HTTPS로 전환)
- Vault가 먼저 기동돼야 PKI 인증서 발급이 가능하므로 구축 마지막 단계에서 진행

```bash
# 1. 위 'Vault PKI 활성화' 섹션 참고하여 vault-01/02/03 인증서 발급

# 2. Ansible 변수에서 TLS 활성화 후 재배포 (컨트롤 노드)
vi ~/ansible/roles/vault/defaults/main.yml
# vault_tls_enabled: true 로 변경

ANSIBLE_CONFIG=~/ansible/ansible.cfg \
  ansible-playbook -i ~/ansible/inventories/prod/hosts \
  ~/ansible/playbooks/vault.yml

# 3. 재배포 후 각 노드 Unseal 필요
export VAULT_ADDR="https://127.0.0.1:8200"
vault operator unseal  # Key 1
vault operator unseal  # Key 2
vault operator unseal  # Key 3

# 4. HTTPS 응답 확인
curl -s https://172.16.30.21:8200/v1/sys/health | python3 -m json.tool
```

**Failover 테스트**
- Raft HA 구성: Active 노드 장애 시 follower가 자동으로 leader 선출

```bash
# vault-01 (Active) 서비스 중단
sudo systemctl stop vault

# 컨트롤 노드에서 vault-02가 leader로 승격됐는지 확인
curl -s http://172.16.30.22:8200/v1/sys/health | python3 -m json.tool
# "standby": false  ← vault-02가 Active로 전환됐으면 정상

# 복구
sudo systemctl start vault

# vault-01 재시작 후 Unseal 필요
export VAULT_ADDR="http://127.0.0.1:8200"
vault operator unseal  # Key 1
vault operator unseal  # Key 2
vault operator unseal  # Key 3
```


## Vault 운영

> **원칙**: Vault 재시작 시 항상 Sealed 상태로 돌아오므로 Unseal 수동 수행 필요

**재시작 후 Unseal**
```bash
# 각 노드에서 실행
export VAULT_ADDR="http://127.0.0.1:8200"
vault operator unseal  # Key 1
vault operator unseal  # Key 2
vault operator unseal  # Key 3
```

**Active 노드 확인**
```bash
# 어느 노드에서든 실행
export VAULT_ADDR="http://127.0.0.1:8200"
vault status | grep -E "HA Mode|Active Node"
```

**Raft 스냅샷 백업 (MinIO)**
- vault-01 (Active 노드)에서 실행
- MinIO mc 클라이언트 사전 설치 및 alias 등록 필요

```bash
export VAULT_ADDR="http://127.0.0.1:8200"

# 스냅샷 저장
SNAP=/tmp/vault-snapshot-$(date +%Y%m%d-%H%M%S).snap
vault operator raft snapshot save "$SNAP"

# MinIO 업로드 (alias: minio / bucket: vault-backup)
mc cp "$SNAP" minio/vault-backup/
rm -f "$SNAP"

# 업로드 확인
mc ls minio/vault-backup/ | tail -5
```

mc alias 등록 (최초 1회):
```bash
mc alias set minio http://172.16.30.70:9000 <ACCESS_KEY> <SECRET_KEY>
mc mb minio/vault-backup
```

**설정 변경 및 재배포**
> 설정 파일 변경 시 handler가 vault 재시작하므로 Unseal 필요

```bash
#  변수 파일 수정 (컨트롤 노드)
vi ~/ansible/inventories/prod/group_vars/vault.yml
# 또는 roles/vault/defaults/main.yml

# 플레이북 실행 (상태 동기화)
ANSIBLE_CONFIG=~/ansible/ansible.cfg \
  ansible-playbook -i ~/ansible/inventories/prod/hosts \
  ~/ansible/playbooks/vault.yml
```


## 트러블슈팅

**Vault가 Sealed 상태**
- **증상**: `vault status`에서 `Sealed: true`, API 요청에 503 응답
- **원인**: 서비스 재시작 또는 노드 재부팅 시 항상 Sealed 상태로 초기화됨
- **해결**: 각 노드에서 `vault operator unseal` 3회 실행

**Raft 클러스터에 노드가 없음**
- **증상**: `vault operator raft list-peers` 결과에 follower 노드 미표시
- **원인**: follower 노드의 vault 서비스 미기동 또는 8201 포트 통신 차단
- **해결**: follower 노드에서 `systemctl status vault` 확인 후 재시작; Unseal 필요

**apt 패키지 잠금 (dpkg lock) 에러**
- **증상**: Ansible 패키지 설치 태스크 중 에러 발생
- **원인**: VM 생성 직후 Ubuntu 무인 업데이트(unattended-upgrades)가 apt를 잠금(lock)
- **해결**: 플레이북 재실행 (common role이 lock 해제 대기 처리함)

**Init 결과 분실**
- **증상**: Unseal Key 또는 Root Token 분실
- **원인**: 초기화 시 출력 결과를 저장하지 않음
- **해결**: 복구 불가 — `vault operator init` 재실행 불가, Vault 데이터 초기화 후 재구축 필요


## K8s 연동 (Vault Agent Injector)

> K8s 파드에 Vault 시크릿을 자동 주입하는 방식 (Agent Sidecar)

**[사전 준비] K8s CA 인증서 및 Reviewer 토큰 추출**
```bash
# [master-01] reviewer ServiceAccount 생성
kubectl create serviceaccount vault-reviewer -n default
kubectl create clusterrolebinding vault-reviewer \
  --clusterrole=system:auth-delegator \
  --serviceaccount=default:vault-reviewer

# [master-01] 토큰 및 CA 인증서 추출
kubectl create token vault-reviewer -n default --duration=8760h > /tmp/reviewer-token
kubectl config view --raw \
  -o jsonpath='{.clusters[0].cluster.certificate-authority-data}' \
  | base64 -d > /tmp/k8s-ca.crt

# [master-01] 파일 vault-01로 전송
scp /tmp/reviewer-token /tmp/k8s-ca.crt kosa@172.16.30.21:/tmp/
```

**K8s Auth Method 활성화**
```bash
# [vault-01]
export VAULT_ADDR="http://127.0.0.1:8200"

vault auth enable kubernetes

vault write auth/kubernetes/config \
  kubernetes_host="https://172.16.30.31:6443" \
  kubernetes_ca_cert=@/tmp/k8s-ca.crt \
  token_reviewer_jwt=@/tmp/reviewer-token

# KV v2 활성화
vault secrets enable -path=secret kv-v2
```

**정책 및 롤 생성**
```bash
# [vault-01]
vault policy write app-policy - <<'EOF'
path "secret/data/app/*" {
  capabilities = ["read"]
}
EOF

vault write auth/kubernetes/role/app-role \
  bound_service_account_names=app-sa \
  bound_service_account_namespaces=default \
  policies=app-policy \
  ttl=1h
```

**Vault Agent Injector 설치**
```bash
# [master-01]
helm repo add hashicorp https://helm.releases.hashicorp.com
helm install vault hashicorp/vault \
  --set "global.externalVaultAddr=http://172.16.30.20:8200" \
  --set "injector.enabled=true" \
  --set "server.enabled=false"

# 설치 확인
kubectl get pods -l app.kubernetes.io/name=vault-agent-injector
```

**파드 annotation 예시**
```yaml
annotations:
  vault.hashicorp.com/agent-inject: "true"
  vault.hashicorp.com/role: "app-role"
  vault.hashicorp.com/agent-inject-secret-config: "secret/data/app/config"
```


## 서비스 인증서 발급

> PKI 활성화 완료 후 수행

**Proxmox 인증서 발급 및 적용**
```bash
# [vault-01] 인증서 발급
vault write -format=json pki_int/issue/internal-services \
  common_name="proxmox.mgmt.local" \
  ip_sans="192.168.34.4" \
  ttl=8760h | tee /tmp/proxmox-cert.json
# 네이밍 규칙: 05.vault-rules.md 참조

jq -r '.data.certificate' /tmp/proxmox-cert.json > /tmp/proxmox.crt
jq -r '.data.private_key' /tmp/proxmox-cert.json > /tmp/proxmox.key
jq -r '.data.ca_chain[]' /tmp/proxmox-cert.json > /tmp/proxmox-ca.crt
```

```bash
# [Proxmox 호스트] 인증서 적용
cp /tmp/proxmox.crt /etc/pve/local/pveproxy-ssl.pem
cp /tmp/proxmox.key /etc/pve/local/pveproxy-ssl.key
systemctl restart pveproxy
```

```bash
# [Packer 실행 머신] CA 신뢰 등록
sudo cp /tmp/proxmox-ca.crt /usr/local/share/ca-certificates/internal-ca.crt
sudo update-ca-certificates
```

적용 완료 후 `packer-ubuntu-template.pkr.hcl`에서 수정:
```hcl
insecure_skip_tls_verify = false
```
